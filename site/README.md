# forkguard documentation site

Static documentation for forkguard: black and white, Manrope, built to be read. No framework, no third-party requests, no inline scripts or styles.

Every page is generated, so the site is always consistent with itself.

```bash
node tools/build-docs.mjs          # or: npm run docs
python3 -m http.server 4173 --directory site
```

Then open http://localhost:4173.

## Where things live

| Path | What |
| --- | --- |
| `tools/docs/pages/*.mjs` | The documentation itself. Edit these. |
| `tools/docs/next.mjs` | The “Where to next” links at the bottom of each page |
| `tools/docs/lib.mjs` | The small block language and the HTML, Markdown and text renderers |
| `tools/build-docs.mjs` | Builds every page, the Markdown copies, the search index and the machine-readable files |
| `site/assets/docs.css`, `docs.js` | Hand-written styles and behaviour |
| `site/assets/brand/` | Logo kit (generated by `tools/build-brand.mjs`) |
| everything else in `site/` | **Generated.** Do not edit by hand. |

## What gets generated

- `index.html` and one folder per page (`commands/fix/index.html`, …)
- A Markdown copy of every page (`commands/fix.md`), for people and language models
- `sitemap.xml`, `robots.txt`
- `llms.txt` (a short index) and `llms-full.txt` (every page as one file)
- `search-index.json`, used by the search box
- `404.html` and `_headers`

## Set the public URL

Canonical links, the sitemap and `llms.txt` need absolute URLs. The default is `https://forkguard.pages.dev`. For any other address, set `SITE_URL` when building:

```bash
SITE_URL=https://docs.example.com node tools/build-docs.mjs
```

On Cloudflare Pages you set it once as an environment variable (below), and every deploy uses it. Pages themselves use relative links, so they work from any path.

## Deploy on Cloudflare Pages

1. In the Cloudflare dashboard, open Workers & Pages, then Create, Pages, **Connect to Git**, and pick the `PRODHOSH/forkguard` repository.
2. Use these settings:

| Setting | Value |
| --- | --- |
| Production branch | `main` |
| Framework preset | None |
| Build command | `node tools/build-docs.mjs` |
| Build output directory | `site` |
| Environment variable `SITE_URL` | your public address, for example `https://forkguard.pages.dev` |
| Environment variable `NODE_VERSION` | `20` |

3. Save and deploy. Every push to `main` publishes the site, and pull requests get preview URLs.

`_headers` is read by Cloudflare Pages: it sets the security headers, a strict Content-Security-Policy, caching, and the right content types for the `.md` and `llms` files. To use a custom domain, add it under the project’s Custom domains tab, then set `SITE_URL` to it so the canonical links and the sitemap match.

After deploying, upload `site/assets/social.png` under the GitHub repo’s Settings, Social preview, and submit `/sitemap.xml` in Google Search Console and Bing Webmaster Tools.

## How the pages are written

Each command page is a manual page (Name, Synopsis, Description, …) and every section is written twice: a **comfortable** version in plain words and a **less comfortable** version, the terse reference text. A switch on each section, and one in the header, flips between them. It follows the idea of the [CS50 manual pages](https://manual.cs50.io/).
